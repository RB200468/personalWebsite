# Project brief

A rough one-pager. Bullets are fine. It doesn't need to be complete: the grilling session fills the gaps.

## Purpose

What is this site for? What should a visitor do or feel after visiting?

- This is going to be a personal website for a devloper, mainly acting as a portfolio and blog
- users should feel they have easy access to the dev's projects and blog posts

## Audience

Who are the visitors (recruiters, clients, peers, friends)?

- This is for both recruiters and other devs and people curios about tech

## Pages and sections

What do you expect to have? (e.g. home, about, projects, blog, contact)

- Home page (I think I want this to contain a brief about section)
- About page (info about the developer)
- blog page (basically just rendered markdown files)
- portfilio (low priority but could embed some github projects)

## Look and feel

Tone, style, colors, typography. Link 2-3 sites you like and say what you like about each.

- simple, clean modern web dev typography that is accessible
- UX is main focus with emphasis on accessibility
- curved edges on shapes
- no colour gradients!
- These selector could be a nice feature, this should be a minimal part that users won't easily find but can change if they like. Include a default light and dark theme along with Atom One Dark and Catpuccin Mocha. 
- MonkeyType.com is a good example to go off for general design inspo (I like their theme selector design)

## Constraints

Hosting, budget, tech you want or want to avoid, deadline, accessibility needs.

- Hosting is not a priority, avoid for now
- Budget is Claude Code Pro plan so keep in mind when working on long complex tasks. you could use cheaper models or lower effort levels where necessesary.
- I am happy with react TS for front end development and would like Spring Java for back end development
- For the time being I am happy with SQLite for storing data
- We should be establishing a contract between the front and back end for data transfer. I suggest we use Swagger 2

## Out of scope for v1

What you're deliberately not building yet.

- Hosting
- Postgres DB integration
- Public comments and likes
- Newsletter

## Open questions

Anything you're unsure about. These are good starting points for grilling.

- I'd like to narrow down the front end design, i have ideas but based on the brief above I'd like to come to a solid understanding between us about what this will look like since due to the cost constraints I want to get this down to as few development loops as possible.

- I would also like to be grilled on back end design implementations
